# 04 Embedding 与向量检索基础

> 向量检索解决的是“哪些文本在语义上接近”，不是“模型已经知道了答案”。它是知识进入上下文前的一次候选筛选。

<details class="case" markdown="1">
<summary>例子：用户换了关键词，搜索结果变成相似但不相关的文档</summary>

用户问“如何撤销自动续费”，向量检索返回了“如何修改付款方式”。两段文本都和付款相关，但没有回答撤销动作。只看相似度分数会把相关性误判成正确性。

!!! note "构造的例子"
    文档标题和结果用于说明语义相似不等于业务相关；实际阈值必须在自己的语料和问题集上测。

</details>

## 从文本到候选片段

```text
文档 → 切块 → embedding → 索引
问题 → embedding → top-k 候选 → 过滤 / 重排 → 上下文
```

Embedding 把文本映射到向量空间。向量距离只能作为排序信号，最终是否相关仍要看问题、权限、时间和文档版本。

## 四个决定结果的参数

| 参数 | 影响 | 常见失败 |
|---|---|---|
| 切块 | 一个候选包含多少语义 | 太小失去上下文，太大噪声多 |
| embedding 模型 | 相似度表达什么 | 领域词汇不在训练分布里 |
| top-k | 给后续多少候选 | 太小漏答案，太大挤满上下文 |
| 过滤条件 | 哪些候选有资格出现 | 权限或版本过滤太晚 |

关键词检索和向量检索各有盲点。产品名、错误码、合同编号等精确词，通常需要 BM25 或数据库过滤；同义表达则更适合向量检索。

## 先检索，再谈生成

不要用模型最后答对了来证明检索正确。先保存问题、原文片段、文档版本、候选排序和过滤原因，再交给生成层。

换 embedding 模型、切块规则或权限过滤逻辑，都要重建并重新评测索引。旧向量和新向量不能直接比较。

## 怎么测

准备带“正确文档 / 正确片段”的问题集，至少测：

- `Recall@k`：正确片段是否进入候选；
- `MRR` 或排名：正确片段出现得早不早；
- 权限泄露率：不属于当前租户的片段是否被返回；
- 新旧版本和删除后的残留率。

检索指标下降时先查切块、过滤和索引，再考虑换模型。
