# 面试地图

> 十个主题，每个从一句开场问题开始，往下两三层追问。**这里不给答案的文本，只给「答到什么算站住了」**——面试里能背下来的东西价值很低，能说清一个机制在什么条件下失效才算懂。
>
> 怎么用：挑一个主题，先自己讲一遍，再对着「答到这些算过」核对。发现说不清的，去「课程」那一行指的课；想看这套东西写成代码长什么样，去「代码证据」那一行。答不上第二层追问是正常的，那正是这份地图要暴露的东西。

## 1. 模型适配：换一家供应商要动多少代码

**在确认什么。** 你是把 SDK 调用散在业务代码里，还是有一层自己的边界。

1. **「一次模型调用在你的代码里经过哪几层？」**
   答到这些算过：SDK 底下就是一次 HTTP POST，请求体的主干是消息、工具定义、抽样参数、模型名；应用只依赖自己的 `ModelAdapter`，供应商差异全关在适配器里面。
2. **追问：「换成 Claude 要改哪些地方？」**
   答到这些算过：工具结果的角色归属变了（Claude 认的是 `user` 消息里的 `tool_result` 块，不是 `role="tool"`）；`max_tokens` 必填；`content` 是块列表，开了思考第一块是 thinking；判断有没有工具调用看 `stop_reason == "tool_use"`。说得出「这几处正是适配器存在的理由」比背字段名重要。
3. **追问：「开了流式，结构化参数怎么处理？」**
   答到这些算过：同一条流上有两个消费者——文本增量可以边到边显示，任何要拿去执行的工具参数必须攒完整、校验过才交出去；`usage` 不保证出现在最后一个事件上。

## 2. Tool Calling：模型说要退款，到真的退款之间发生了什么

**在确认什么。** 你有没有把「模型的输出是建议」这条落成代码。

1. **「模型返回一个 `refund` 调用，你的代码接下来做什么？」**
   答到这些算过：一串固定顺序的守卫——工具名存不存在、这个场景允不允许用、参数合不合 schema、要不要人确认、幂等键、然后才执行。每一道失败都变成回喂给模型的错误结果，不抛异常打断循环。
2. **追问：「白名单为什么不能写在提示词里？」**
   答到这些算过：提示词是概率性的，它给不了边界；边界必须由代码执行。能举出「一段用户输入就能让模型请求它不该调的工具」这类场景更好。
3. **追问：「哪些动作该弹确认？」**
   答到这些算过：按可逆性分级。可撤销的直接做、给一个撤销窗口；不可逆的才问。每个动作都弹确认，用户三分钟后就开始无脑点同意，确认门等于没有。

## 3. 幂等与恢复：进程崩在最坏的那一瞬间

**在确认什么。** 这是最能分出「做过生产」和「做过 demo」的一题。

1. **「工具调用超时了，你重试吗？」**
   答到这些算过：重试要看错误类型，不看次数；带幂等键重试。键要两层——一层从 `tool_call.id` 派生挡「同一次调用的重试」，一层从业务侧稳定的 id 派生挡「模型重发同一个意图」。只用 `tool_call.id` 会漏第二种。
2. **追问：「进程崩在「钱已经出去了、结果还没写进数据库」那一瞬间，恢复时会怎样？」**
   答到这些算过：这次调用在恢复时仍然属于「问了但没结果」，于是会被再执行一次。**checkpoint 保证的只是本地事件不重复，保证不了外部副作用不重复。** 把顺序倒过来（先记后执行）会换成「记了没做」，动作静默丢失，更难查。
3. **追问：「那怎么办？」**
   答到这些算过：三条按代价排——外部幂等键最省事；本地先落一条「我要做了」（`tool_started` / outbox），让崩溃点可查；拿键去外部系统查这笔成没成，查不出来的落进人工对账队列。关键是承认「做没做不知道」是第三种状态，别把它当成「没做」。副作用就在自己数据库里的，业务写入和事件放同一个事务就够。
4. **追问：「用 LangGraph 呢？」**
   答到这些算过：`interrupt()` 恢复要传 `Command(resume=值)`，而且节点会从头重跑——`interrupt()` 之前的语句再执行一遍。框架能管好自己的状态，管不了你在节点里调的那个外部接口。

## 4. RAG 排错：一句「答错了」怎么定位到层

**在确认什么。** 你是猜哪一步坏了，还是有一套证据能把其他步排除掉。

1. **「用户说答错了，你从哪查起？」**
   答到这些算过：七步各有各的坏法——解析、切块、embedding、索引、检索、重排、生成。定位靠三样证据摆在一起：原文那一块、这次检索的 top-k、最后送进模型的那段上下文。三样一摆，坏在第几步是确定的。
2. **追问：「怎么区分「压根没检索到」和「检索到了模型没用」？」**
   答到这些算过：看 top-k 里有没有那一块。有而没用是生成层的事（引用校验、提示词），没有是检索层的事（BM25 和向量分别算 Recall@k，看各自漏什么）。
3. **追问：「块大小和 overlap 怎么定？」**
   答到这些算过：没有通用值，用 Recall@k 在自己语料上调；经验起点 300～800 字符加一段重叠。overlap 让索引变大多少取决于块大小和重叠策略，别背固定比例，入库前后数块数。换 embedding 模型必须重建全部向量。

课程：[15](../lessons/rag-end-to-end/README.md) · [04](../lessons/embeddings-and-vector-search/README.md) · [17](../lessons/data-engineering/README.md) ｜ 代码证据：`knowledge/ingest.py`、`knowledge/hybrid.py`、`knowledge/retriever.py`、`knowledge/citations.py`

## 5. 评测：凭什么说这次改动变好了

**在确认什么。** 「我感觉更好了」和一份能拦住回归的门禁之间的距离。

1. **「改完 prompt 你怎么验证？」**
   答到这些算过：先分清五件事——确定性断言、录制回放、拿真模型跑 golden set、LLM judge、线上实验，各自要什么、各自能证明什么。断言和回放不调模型，所以能进每次提交的 CI；也正因为不调模型，它们回答不了「今天这版 prompt 好不好」。**CI 绿灯的含义是「评测这套代码没坏」。**
2. **追问：「judge 和人的一致率 85%，够信它了吗？」**
   答到这些算过：先算 kappa。一个「全判 pass」的 judge，在 58% 案例本来就该 pass 时一致率也有 58%，kappa 是 0。经验阈值 0.4 以下不可用、0.6 以上才谈得上可信。
3. **追问：「怎么保证 kappa 不是调出来的？」**
   答到这些算过：调 judge 用的那批标注和验收 judge 用的那批要分开。同一批数据反复迭代，kappa 会涨到 0.9，换一批新样本就掉回去。
4. **追问：「总分没降，用户还在骂，为什么？」**
   答到这些算过：总分掩盖切片。门禁要按切片各自比基线，切片消失当零分处理（有人删掉对抗案例，门禁要报错）。

## 6. 可观测性：一次回答背后有八九次调用

**在确认什么。** 你的日志能不能支持排查，还是只留下了最后那句错误回答。

1. **「线上一个 bad case，你怎么查？」**
   答到这些算过：一次请求一棵 span 树，模型调用、工具执行、检索各是一个 span，上面挂着输入输出、token 用量、耗时。查的时候看的是这棵树，不是零散日志。
2. **追问：「属性名自己起还是用标准的？」**
   答到这些算过：用 OpenTelemetry 的 GenAI 语义约定（`gen_ai.operation.name`、`gen_ai.request.model`、`gen_ai.usage.input_tokens` 这些），span 名按 `{operation} {model}`。标准化之后换后端是改配置的事。
3. **追问：「trace 里不该记什么？」**
   答到这些算过：密钥、完整的用户隐私数据；大 payload 要截断或采样。trace 自己也有成本和合规边界。

## 7. 容量与成本：这个服务要几台机器

**在确认什么。** 你会不会先写假设再算数，以及会不会把一个数套到所有池子上。

1. **「五万日活的对话服务，要备多少并发？」**
   答到这些算过：先列假设表——日活、每人每天几轮、每轮输入输出 token、峰值是均值几倍、p95 一轮多久、单价。每个数字能追溯到一个来源。然后 `平均 rps = 日轮次 / 86400`，`峰值 rps = 平均 × 峰值因子`。
2. **追问：「并发数怎么来的，Little's law 吗？」**
   答到这些算过：Little's law 是 L = λ × W，前提是稳态，λ 和 W 都是平均值。工程上常用峰值 rps × p95 停留时间，两个都往大取，得到的是峰值时段的保守上界，不是定律算出来的平均在途数。说得出这个区别，这一题就站住了。
3. **追问：「这个数能当数据库连接池大小吗？」**
   答到这些算过：不能。每种资源的停留时间不一样——模型并发看单次调用耗时，SSE 连接看整轮加收尾，数据库连接只占每轮的百分之几，队列长度归排队模型那套。拿整轮 p95 去开连接池，池子会大出几十倍。
4. **追问：「钱太多了怎么降？」**
   答到这些算过：前缀缓存和便宜模型路由只动成本、不动容量；要动容量得动 p95 或者每轮输入 token。所以延迟优化同时也是容量优化。

## 8. Workflow 还是 Agent：这个需求要不要放开让模型决定

**在确认什么。** 你会不会为了用 Agent 而用 Agent。

1. **「这个需求你打算怎么做？」**
   答到这些算过：先问「能不能不用 Agent」。workflow 是模型和工具按预先写好的代码路径走，agent 是模型自己决定过程和工具用法；两者的差别是可预测性和灵活性的交换，不是先进和落后。
2. **追问：「什么信号说明该上 Agent？」**
   答到这些算过：步骤依赖前一步的中间结果、分支组合多到写不完、每次任务的形状都不一样。反过来，流程写得出来就写死，它更好测、更好查、更便宜。
3. **追问：「任务变成几十步怎么办？」**
   答到这些算过：两条路。拆成几个小 Agent（一个管 3～10 步）靠隔离上下文，代价是交接、视图计算、多一层 trace；不拆而上一份清单每轮回注，靠重复目标对抗漂移，代价是上下文长期占一块。任务能干净切块的拆，切不开的上清单。
4. **追问：「上了清单，模型报告完成就算完成吗？」**
   答到这些算过：不算。每项配一条能跑的验收命令，「完成」由代码判定。而且要分清命令跑成功、验收条件成立、这一项做完是三件事——`grep ... | wc -l` 这种管道的退出码永远是 0，拿它当验收等于没验。还要防模型在改计划时把项数或验收标准改松。

## 9. MCP：把工具接入变成接协议

**在确认什么。** 你知道它解决什么、以及它不解决什么。

1. **「MCP 解决什么问题？」**
   答到这些算过：把「每个工具在每个应用里接一遍」变成「一个 server 接一次，任何 host 都能用」。传输上是 JSON-RPC（本地常走 stdio），握手之后 `tools/list` 拿到工具契约，`tools/call` 调用。工具的 schema 从远端来，但校验、白名单、幂等这些守卫仍然在你的运行时里。
2. **追问：「server 升级了、参数改名了，你缓存的工具列表怎么办？」**
   答到这些算过：缓存什么时候失效三家框架都不替你决定。要么每次握手重新拉、要么按版本号失效，并且参数校验失败时能给出「你调的是旧 schema」这类可诊断的错误。排查先用 MCP Inspector 连上去看 `tools/list` 实际返回什么。
3. **追问：「错误怎么分类？」**
   答到这些算过：参数不对（JSON-RPC 的 `-32602`）是回喂给模型让它改的那一类；server 进程挂了算瞬时错误，重连一次；权限拒绝要直接停下来交给人。

## 10. 多 Agent 与 handoff：拆开之后谁说话算数

**在确认什么。** 你是把「多 Agent」当架构目标，还是当一个有代价的选项。

1. **「什么时候要拆成多个 Agent？」**
   答到这些算过：一个 Agent 可靠地管 3～10 步，任务更大就拆。拆的收益是每个子任务的上下文短、职责清；代价是交接协议、每个 Agent 看到什么的视图计算、以及多一层 trace 要排查。工具只有五个的时候拆开，只是把问题换成消息传递。
2. **追问：「交接的时候历史给多少？」**
   答到这些算过：这条策略由运行时决定，不由任何一个 Agent 决定。给全等于没拆（上下文照样长），给太少专家 Agent 干不了活。所以要有一个显式的视图函数，而且这一行策略值得单独评审。
3. **追问：「两个 Agent 并行跑，谁的输出算数？」**
   答到这些算过：仲裁规则写在代码里——先到先得、按置信度、还是要求一致，都行，但必须是确定性的，而且要记进 trace。让两个 Agent 自己商量出结果，等于把仲裁交给了概率。

## 还剩两件事

**说不清楚的地方，别绕。** 面试里最好的回答之一是「这个我只在 demo 规模上做过，生产上我会先量这三个数」。带条件的答案比含糊的肯定句可信得多。

**每一题都可以反过来问自己：** 我手上那个系统，这一层的证据在哪里？拿不出证据的层，就是下一个该补的地方。完整的出师标准在[课程总览](../lessons/README.md)最后一节。
