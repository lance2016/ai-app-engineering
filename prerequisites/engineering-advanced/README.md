# 工程能力进阶：把系统当成一项长期运行的服务

> 这组页面写给已经做过几年后端、能读懂基础页的人。重点从“这个功能怎么写”移到“系统对用户承诺什么、失败时怎么恢复、改动怎么回滚、凭什么决定继续投入”。
>
> 先看基础页，再按下面的能力域进入主线第 07、17–22、26 课和参考项目 M2–M6。每页都给一个判断问题、参考实现落点和继续深入的资料。

## 先建立一张进阶地图

| 能力页 | 要回答的问题 | 主线与参考实现 |
|---|---|---|
| [分布式执行](./distributed-execution.md) | 进程重启、重复请求、乱序事件和下游超时后，状态怎样恢复？ | 第 07、18 课；`runtime/loop.py`、`storage/postgres.py` |
| [可靠性与容量](./reliability-capacity.md) | 延迟、成功率、成本和并发的目标是什么？过载时先保护谁？ | 第 19–21、26 课；`ops/resilience.py`、`ops/ratelimit.py` |
| [数据演进与异步工作流](./data-evolution-workflows.md) | 哪份数据是事实，迁移、删除和长任务怎样不留脏状态？ | 第 15–17、21 课；`storage/migrations/`、M3/M4 |
| [多租户与安全架构](./multi-tenant-security.md) | 谁能看到什么、调用什么、改变什么？边界在哪一层执行？ | 第 13、22、26 课；`runtime/registry.py`、`security/` |
| [评测与观测](./evaluation-observability.md) | 模型、提示词或数据变了，怎样知道质量和成本哪里变了？ | 第 19、20 课；`eval/`、`ops/telemetry.py` |
| [架构决策](./architecture-decisions.md) | 为什么现在选这个方案，什么证据出现时要换？ | 第 23、26 课；M6、capstones |

本页所有参考实现路径按仓库 `main` 分支核对，访问日期为 2026-09-10；仓库会继续演进，读者以当前版本为准。

## 给有工作经验读者的路线

| 顺序 | 读什么 | 读完要能回答 |
|---|---|---|
| 1 | M2 + 第 07、18 课 | 进程重启、重复写入和并发冲突时，哪份状态是事实？ |
| 2 | M3 + 第 05、06、09、12、13 课 | 模型建议、工具副作用和第三方能力之间，哪些边界由代码守住？ |
| 3 | M4 + 第 15–17 课 | 文档更新、删除和引用校验怎样沿派生链保持一致？ |
| 4 | M5 + 第 19–22 课 | 一次质量或成本退化，能否从评测切片和 trace 定位到具体层？ |
| 5 | M6 + 第 23、26 课 | 什么时候该换模型、拆服务或引入框架，退出条件是什么？ |

外部路线可以按“可靠性 → 数据 → 安全 → 观测”补：先读 [Google SRE Book](https://sre.google/sre-book/introduction/)，再看 PostgreSQL 的事务和并发控制、OpenTelemetry 的上下文传播、OWASP ASVS。上述资料访问日期均为 2026-09-10。

## 这组页面暂时不展开什么

共识算法、跨地域复制、Kubernetes 控制器、内核网络调优、GPU kernel、服务网格和完整身份平台都是真正的进阶主题，但当前课程的参考项目没有这些实现。遇到相关工作时，再按实际约束单独补；不要为了“像大厂架构”提前引入一套自己无法观测和回滚的基础设施。
