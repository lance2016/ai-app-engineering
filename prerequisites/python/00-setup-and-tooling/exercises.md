## 练习 1：跑通并改一行

运行 `code/01_hello.py`，然后把 `"Hello from Python!"` 改成一句你自己的话，再跑一次。

验收：终端第一行是你改的那句话，第三行的路径里包含 `.venv`。

<details><summary>提示</summary>

用 VS Code 打开文件改字符串，保存，回到终端按上箭头找到刚才的命令回车。如果路径里没有 `.venv`，说明你用了 `python` 而不是 `uv run python`。

</details>

## 练习 2：在 REPL 里验证一件事

打开 REPL（`uv run python`），不看资料，用它回答：`"3" + "4"` 是什么？`3 + 4` 是什么？`"3" * 3` 是什么？

验收：三个结果都亲眼看到，并能用一句话说出为什么第一个不是 7。

<details><summary>答案</summary>

`"3" + "4"` 得到 `'34'`，因为引号里的是文本，`+` 对文本是拼接。`3 + 4` 得到 `7`。`"3" * 3` 得到 `'333'`，文本乘整数是重复。P01 会正式讲类型。

</details>

## 练习 3：删掉环境再重建

删掉仓库里的 `.venv` 文件夹（macOS/Linux：`rm -rf .venv`），然后 `uv sync`，再跑 `code/02_where_am_i.py`。

验收：`uv sync` 不到一分钟跑完，脚本输出和删之前一样。

<details><summary>答案与目的</summary>

这题是为了让你亲手确认：`.venv` 是可再生的，坏了就删，不需要修。以后遇到"环境莫名其妙不对"，这是最快的修法。它不该进 git，仓库的 `.gitignore` 已经排除了它。

</details>
