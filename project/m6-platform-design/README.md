# M6 综合设计

> 设计型里程碑，不写代码。它同时是 [Capstone 4 Multi-tenant AI Platform](../capstones/04-multi-tenant-platform/README.md) 的设计阶段：这里写 RFC，Capstone 把 RFC 里最关键的切片实现出来。用前面五个里程碑的真实经验，为一个面向多租户的"知识库 + 任务 Agent"平台写一份 RFC：容量、成本、威胁模型、模型与推理选型、迁移与退出。验收的是文档质量，不是页数。

## 这一步加什么

一份 RFC，用下面的模板。每一节都要引用前面里程碑的真实数字或事故，不能只写原则。

```markdown
# RFC-001: 多租户知识库与任务 Agent 平台

## 1. 背景与目标
- 现状（M1–M5 已有什么，痛点是什么）
- 目标（可度量：租户数、日请求、SLO）
- 非目标（明确不做什么）

## 2. 约束
- 数据驻留与合规；删除时限
- 团队规模与上线时间
- 预算上限

## 3. 方案概览
- 一张架构图（第 16 课的请求链加租户边界）
- 数据模型（租户 id 在每张表的位置）

## 4. 关键决策（每条一份 ADR，用第 23 课 02_adr.py 的格式）
- ADR-1 租户知识：RAG / 微调 / 长上下文
- ADR-2 控制流：Workflow 与 Agent 的边界
- ADR-3 评测与 trace 平台：自建 / 买 / 自托管
- ADR-4 模型与推理：托管 API / 自托管开源 / 混合，含路由与 Fallback（第 21 课）

## 5. 容量与成本
- 第 23 课 01_capacity_estimator.py 的假设表和三个场景
- 并发运行数 → 工作进程与连接池；事件写入速率 → 数据库规格

## 6. 威胁模型
- 提示注入、越权访问他租户数据、MCP / Skill 供应链、成本攻击（第 20 课）
- 每条威胁对应的代码级防线，不是提示词

## 7. 质量运维
- SLO（首 token 延迟、任务成功率、错误引用率）与告警
- 回滚对象：提示词版本、Skill 版本、模型版本
- 故障演练计划

## 8. 交付计划
- 三期：单租户单体 → 多租户隔离 → 平台化
- 每期的退出条件

## 9. 失败场景推演
- 至少五个：供应商全挂、某租户流量暴增、检索索引损坏、Skill 被投毒、删除请求未在时限内完成
- 每个写出系统行为、用户看到什么、谁被告警

## 10. 未决问题
```

## 验收证据

<!-- 设计型里程碑：不要求代码。 -->

- [ ] 架构图与数据模型：租户边界在图上可见，每张表标出租户列
- [ ] 容量估算与成本模型：假设表完整，三个场景的每日花费有数字，杠杆收益有排序
- [ ] 威胁模型：至少六条威胁，每条对应一个代码级防线和一个测试
- [ ] SLO 与告警方案：三条 SLO 各有度量方式和告警阈值
- [ ] 至少三份 ADR，每份有备选方案和可观测的退出条件
- [ ] 失败场景推演：五个场景，每个写清系统行为、用户体验、告警对象
- [ ] 迁移方案与退出机制：从 M5 的单租户到多租户的迁移步骤，以及每期的退出条件
- [ ] 找一个人做一次评审，把评审问题和修订记录附在 RFC 末尾
